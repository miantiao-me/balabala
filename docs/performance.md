# 渲染、导入与存档性能

下方“优化入口”与“宿主测量”记录此前以提交`fe1bc25`为对照的优化，在相同宿主、相同卡片与相同release配置下比较CPU耗时。本轮新增结果见[发布前复测](#4000-卡索引查找与最新宿主基准发布前复测)。保留MicroTS页面、唯一48000 B帧缓冲、7680 B条带和现有刷新策略。宿主数据用于定位CPU开销；真实翻页还包括C3执行、SPI传输与墨水屏刷新。

## 优化入口

- [静态叠加](../native/src/overlay.rs)：圆角填充和焦点反白按行计算边界，中间按整字节写入；字形和素材直接移位合并1bpp源字节，保留帧外裁剪及末字节padding规则。
- [黑白转换](../native/src/render.rs)：八像素全白块以及纯黑、纯白像素走快路径，其余RGB565颜色保留原亮度权重与阈值。
- [字体预算](../native/src/model/view.rs)：消费已经生成的临时View，避免为三种存储提示状态再深拷贝一次全部字符串。
- [存档校验](../native/src/model/save.rs)：IEEE CRC32使用64 B只读四位表，每字节两次查表；初值、最终取反、分块和记录格式保持。

优化没有引入页面缓存或额外运行时heap。配网活跃期仍使用固定面板更新，评分、显示确认、存档保护及关机流程继续遵守既有契约。

## 宿主测量

基准位于[test-performance.rs](../tools/test-performance.rs)，默认忽略，显式运行。使用`native/Cargo.toml`的release配置（`opt-level=s`、LTO、单codegen unit）；每项取五批的单次操作耗时中位数。页面每批12次，叠加每批48次，导入每批3次，CRC每批64次，存档导出每批32次。叠加计时包含恢复基准帧缓冲，完整渲染计时包含AOT挂载、文字栅格化、黑白打包和静态叠加。分配计量单独执行，不进入耗时区间。

| 操作 | 优化前 | 优化后 | 耗时下降 |
| --- | ---: | ---: | ---: |
| 首页完整渲染 | 0.867 ms | 0.493 ms | 43.1% |
| 认一认正面 | 0.583 ms | 0.247 ms | 57.6% |
| 认一认背面 | 0.620 ms | 0.303 ms | 51.1% |
| 四选一答题页 | 0.602 ms | 0.283 ms | 52.9% |
| 答题反馈页 | 0.678 ms | 0.292 ms | 56.9% |
| 学习情况页 | 0.623 ms | 0.279 ms | 55.2% |
| 汉字32卡解析与校验 | 0.836 ms | 0.788 ms | 5.7% |
| 英语32卡解析与校验 | 1.029 ms | 0.950 ms | 7.7% |
| 32KiB CRC32 | 208.261 μs | 104.619 μs | 49.8% |
| 当前学习状态导出 | 2.126 μs | 1.230 μs | 42.1% |

两次导入分别从11942 / 13119降为11139 / 12316次分配请求，各减少803次；这指分配器请求次数，不是同时存活对象数。导入heap峰值仍为12816 / 12851 B。六种页面的render峰值与分配请求次数均保持原值，最大为42417 B。完整页面集合的峰值由[验收记录](acceptance.md#性能优化)单独报告。

这些是宿主样本，不是C3的毫秒数或屏幕提速百分比。导出计时仅包含Rust序列化及校验，不包含SD写入、flush或sync；没有测电流或续航。微基准受系统调度和CPU频率影响，因此不使用时间阈值作为CI门槛。

## 4000 卡索引查找与最新宿主基准（发布前复测）

本轮以提交 `3912a6b` 的原始宿主结果作为导入与渲染基线，前后均使用相同内容及 `opt-level=s` release 配置。每项先预热，再测五批；每批总耗时除以操作次数，最后取五批的中位数。原始数据位于 `.build/release-review/baseline-performance.json` 与 `final-performance.json`，对比汇总为 `final-performance-comparison.json`。

### 4000 卡索引查找优化

课程查询复用已有的 FNV32 有序索引，替代按 ID 全目录线性扫描，命中后仍比较科目与完整 ID。下表在同一次基准中测量原线性算法和新查询算法：每批遍历全部 4000 个 ID 三次，换算为一次完整目录遍历的耗时。

| 操作 | 线性扫描耗时 | 索引二分查找耗时 | 宿主加速比 |
| --- | ---: | ---: | ---: |
| 依次查询全部 4000 个 ID | 6,460,833 ns | 125,305 ns | 51.56 倍 |

**说明**：51.56 倍为宿主 CPU 在 4000 卡目录中检索卡片 ID 的算法加速比，**不能等同于 C3 整机系统提速，更不代表电子墨水屏翻页提速**（墨水屏物理刷新仍受硬件驱动与控制器传输周期主导）。

### 解析导入与内存

| 操作 | 优化前耗时 | 优化后耗时 | 耗时变化 | 分配请求变化 | 堆峰值变化 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 汉字 32 卡解析与校验 | 812,055 ns | 770,152 ns | -5.16% | 11,523 → 8,754 (-24.03%) | 12,816 B → 12,816 B (持平) |
| 英语 32 卡解析与校验 | 1,019,541 ns | 957,055 ns | -6.13% | 12,623 → 9,664 (-23.44%) | 12,851 B → 12,851 B (持平) |

**边界提示**：

- **分配请求次数**指内存分配器的调用次数，不代表同时存活的对象数量；
- **宿主堆峰值**由宿主 64 位环境测得，不能等同于 ESP32-C3 运行时的动态 heap 及最大连续块。

### 页面渲染与存档

- **六种页面渲染**：所有页面的分配请求次数与堆峰值严格保持不变（首页峰值 30,424 B / 169 次分配；认一认正面 30,372 B / 169 次；背面 32,961 B / 198 次；四选一 42,126 B / 248 次；反馈 43,479 B / 253 次；统计 30,550 B / 183 次）。渲染耗时变化为 -25.88% 至 +2.5%，结果有涨有跌；该组样本不足以判断各页面的稳定耗时收益或把变化归因于系统调度。
- **CRC32 与存档导出**：32KiB CRC32 耗时为 104,374 ns → 103,754 ns（-0.59%），存档状态导出耗时为 4,147 ns → 4,135 ns（-0.29%），性能基本持平。

本轮还去除了默认首页、首卡正面上翻及单项菜单的无效 revision 更新，减少这些操作触发的显示与保存请求；配网完整帧不再重复绘制状态面板，仍保留终态身份擦除。回归测试核对 revision、dirty 和图像输出，本轮未测量设备上的刷新次数或物理翻页耗时。

## 复现与回归

先在仓库根目录运行完整宿主测试，生成`.build/native/`和资源，再通过项目环境脚本加载固定工具链：

```sh
sh tools/build.sh test
root="$PWD"
. tools/env.sh
export BALABALA_GENERATED="$root/.build/generated"
BALABALA_PERFORMANCE_OUT="$root/.build/performance/sample.json" \
CARGO_NET_OFFLINE=true rustup run "$RUST_VERSION" cargo test --locked --release \
  --manifest-path .build/native/Cargo.toml --lib \
  tests::performance_render_import_and_save -- --ignored --exact --nocapture
```

前后比较使用同一份基准、同一组内容和同一编译配置，基准文件需在两份运行时源码上保持一致。默认回归跳过耗时测量；需要debug配置检查基准入口时，可用`sh tools/build.sh test tests::performance_render_import_and_save -- --ignored --exact --nocapture`。

[test-overlay.rs](../tools/test-overlay.rs)比较逐像素语义与字节写入结果，覆盖八种位对齐、负坐标、边缘裁剪、padding、圆角与反白；[黑白转换回归](../tools/test-render-core.rs)遍历全部65536种RGB565颜色；[存档回归](../tools/test-save.rs)包含IEEE已知向量、分块一致性和旧位算法生成记录的恢复。冻结View还需重放并逐字节比较PBM，以验证字体、框线、焦点和最终提示输出。

原始JSON、完整日志、源码快照和候选位于`.build/performance/`，均排除在Git之外。精确验证命令、固件尺寸和未测项目见[性能验收](acceptance.md#性能优化)。
