# 学习应用与平台接口

应用层由 [Rust 模型](../native/src/model.rs)、[MicroTS 页面](../native/App.vue) 和 [C ABI](../firmware/main/balabala_probe.h) 组成。平台在同一任务串行传入按键、卡组、存档和配网状态；常规页面通过生成的 props 绑定渲染，配网的两次准备帧之后仅更新固定面板。显示、ADC、SD、关机和 BLE 服务已接入[平台运行时](platform.md)，当前候选的宿主、构建及真机边界见[首版验收](acceptance.md)。模块职责和测试定位见[代码结构](architecture.md)。

## 页面与学习行为

学习模式、反馈、按键和家长入口统一见[产品设计](product.md#页面与学习闭环)，课程调度、累计正确次数与 80% 解锁规则见[课程说明](curriculum.md#学习与进度)。模型按稳定 ID 保留每题结果，同题每轮只评分一次；翻面、跳过和回看不评分，反馈等待主动翻题。示范卡轮换覆盖未学会卡片，复习只选未学会的错题稳定 ID。

`Home` 返回首页并保留轮次，`Shutdown` 产生平台关机请求。平台先保存并等待网络资源明确释放，模型复核 dirty 和待显示帧后才允许静态休眠页；保存错误保留提示。短长按识别、去抖和真正关机属于平台职责。

屏幕逻辑尺寸固定480×800。文字由MicroTS strict AOT排版，原创图标、框线、进度点、键帽、插画和特大字由Rust直接叠加到1bit帧缓冲，不创建图片heap副本。几何源为[ui-layout.ts](../tools/ui-layout.ts)，模板与Rust共用生成坐标；配网单独使用[provisioning-layout.json](../native/provisioning-layout.json)。字号槽为12=24px、6=32px、15=48px，均使用霞鹜新晰黑v1.308的同一字重；5=24px Noto Regular、14=48px Noto Regular保留旧冻结View、原导入宽度度量及刷机最终提示。MicroTS样式中的text-4xl和text-5xl使用这些固定槽，不代表完整浏览器CSS或TypeScript。

## 输入与显示时序

平台调用 `balabala_app_create()` 后，以同一任务串行操作对象。`balabala_app_key(app,key,pressed)` 的 key 取值见头文件，pressed 必须为 0/1。正面和侧面键都要传松开事件，刷新繁忙时也不能遗漏。

`balabala_app_status()` 返回位：1 需要刷新、2 等待显示完成、4 存档有变化、8 下载事务中、16 下载提示页、32 网络持有面板与资源。下载请求/取消、专属 revision 确认及恢复边界见[刷机模式](download-mode.md)。`balabala_app_render()` 输出 48000 字节 1bit 图像及 revision，使用另一个 480×8 RGB565 条带缓冲；1 表示没有可绘页或上一帧还在显示。只有物理显示确实完成后，平台才能调用 `balabala_app_display_complete(revision)`。旧 revision 不会放开新题门禁；导航期间累积的状态合并为下一次最新页面，不创建无界刷新队列。

`balabala_app_clear_interval(app)` 返回家长选择的连续局刷上限 8 / 16 / 32 / 64 / 128，空指针返回默认 8。该设置随现有 v2 存档保存，读取缺少此字段的 v1/v2 存档时默认 8；其他值使该槽语义无效，仍按双槽恢复规则处理。平台每次刷新前读取上限，不重置驱动已有计数，也不取消关键页全刷。

正面按键必须同时满足“当前 revision 已显示”“没有等待完成的显示”“此前所有键已释放”才会操作页面或作答。侧面导航允许在显示繁忙时改变目标。Home/Shutdown 请求不受该门禁阻塞。物理电源长按只产生 Shutdown；平台不能先产生 Home 再补 Shutdown。

帧缓冲逻辑位序为行优先、MSB 在左、1 白/0 黑。X4 物理屏为 800×480，旋转方向和转置须由实际板驱动验证。缓冲及对象不得重叠，所有指针生命周期、对齐和串行调用要求见头文件；OOM/panic 会记录并终止，不跨 ABI unwind。

## 内容包

完整SD课程的目录、GB2312/NGSL边界、单元与累计掌握规则见[小学课程与累计掌握](curriculum.md)。下面的小卡组接口继续用于无完整课程包的示范与自定义内容。

[JSON Schema](../content/schema.json)版本为1。四个手工维护的示范源为[汉字](../content/hanzi.json)、[拼音](../content/pinyin.json)、[英语](../content/english.json)、[数学](../content/math.json)，各32张，合计128张；每卡四个不同选项、一个0–3的正确索引和解释。英语示范为版本3，其余为版本2。为满足NGSL边界，三个水果词使用新ID的词卡替换；旧ID退役和进度迁移见[双槽迁移](curriculum.md#双槽迁移)，其余125个旧ID保留。示范文字及[黑白SVG素材](../native/art)为本项目原创，构建时烘焙为1bpp静态数据。未包含真实密码或个人数据。

一个 UTF-8 JSON 包包含 schema/min_format/version、卡组 id/subject/title 和 cards。四科各保留一个活动包，每包最多 40 卡，最多 65536 字节；稳定 ID 仅允许 1–32 个小写 ASCII 字母、数字、连字符。运行时拒绝未知字段、纯空白字段、重复卡片ID、排版后相同的选项、错误答案索引、缺字、过长或无法完整显示的字段。原始文本保留；排版统一折叠连续空格，并按最终显示内容判断选项是否重复。

| 字段 | 字符上限 | 运行时显示限制 |
| --- | ---: | --- |
| title | 16 | 24px 宽度≤280 |
| front | 12 | 48px 宽度≤424，须有大字号字形 |
| question | 32 | 24px 宽度≤424 |
| 每个 option | 16 | 24px 宽度≤370 |
| back / explanation | 64 | 每字段≤192字节，24px 换行后≤3行 |

平台完成 SD 读取后，通过 `balabala_app_import_deck(bytes,length)` 提交完整包。全部验证成功才替换该科；同一 deck.id 不允许版本倒退。更新保留仍存在的 `(subject,card.id)` 进度和已答结果；重排卡片不会按新数组位置移动结果，恢复仍按原轮次 ID 定位。活动轮次有 ID 被删除则终止该轮，保留其他有效进度。缺失、损坏、超限、缺字返回错误并显示可退出页面，原卡组和进度保留。

字段的原始字数、宽度和三行解释限额保持；宽度校验沿用原Noto字形度量，实际页面再按霞鹜新晰黑排版。新模板额外复用[fit.rs](../native/src/fit.rs)进行导入校验和View生成：问题优先48px再退24px；选项整题选择48 / 32 / 24px中能完整排下的最大字号，分别最多2 / 4 / 6行；西文词和数字尽量整体保留，24px兜底才逐字拆词。折行使用实际字形advance，并避免收尾标点落到行首；不截断字段。

字段校验之后还要通过两项容量限制：

- **每页字体逻辑构造预算最多83807字节。** 复用实际卡组页和学习页组装逻辑，逐卡检查认一认正/反面、未答题、答错/答对反馈，以及轮长1–10、所有合法游标组合。新页面按实际AOT分支的字号/文字集合计费，包含替代字形；bitmap从Flash借用，预算与实际cmap分配分别报告。新模板按1bpp覆盖计费，旧冻结模板保留原8bit等效口径，数值不能跨口径直接比较；原门禁未降低。历史22000学习状态的预算证据见[内存记录](font-flash-oom.md)，当前结果见[UI验收](acceptance.md#ui-与-ux-重写验收)。
- **四科活动内容合计最多 32768 字节的 C3 容量计费。** 卡组 Vec 每个分配槽预留 64 字节、卡片 Vec 每槽 112 字节，再加全部字符串的实际 capacity；32 位交叉编译会断言结构大小不超过这两个值。内置128卡计费为30221字节。限制针对替换后的四科总和，40 卡/包和 64KiB/包仍是语法上限，内容可能先触及常驻限额。

字体估算与加载共享字符集合及Vec容量算法。新模板每字号有`g`个不同字形时，逻辑等效字档大小为`16 + g × (8 + ceil(cellWidth / 8) × cellHeight)`；旧冻结模板仍用`16 + g × (8 + cellWidth × cellHeight)`保持历史口径。逻辑预算取各字号构造时的“此前等效驻留payload + 当前字符Vec capacity × sizeof(char) + 当前等效payload”的最大值，payload不含16字节头。实际加载只分配字符表和cmap，bitmap借用Flash；字号按5 / 6 / 12 / 14 / 15依次处理，没有文字的槽不加载。不能把单字段预算相加代替整页检查，也不能把逻辑计费视为整机heap。

固件内24px / 32px / 48px字档使用DCFA v3 mono：16 字节头、8 字节 cmap 与版本号保持，头部 byte 13 的 `FLAG_MONO1 = 2` 区分单色存储。density 固定为 1，每字形保存 `cellHeight` 行，每行 `ceil(cellWidth / 8)` 字节，高位在左；原覆盖度 `>=128` 的位为 1，解码为 255，否则为 0，行尾未用位清零。实际字档大小为 `16 + g × (8 + ceil(cellWidth / 8) × cellHeight)`。旧 8bit 字档仍可加载；mono 拒绝其他密度及动态 streaming 配置，detach 保留。格式与实现由[固定补丁](../patches/README.md)维护。

第1阶段实测5号槽24px / 606字形 / 24×35为68494 B，14号槽48px / 284字形 / 48×70为121568 B；合计190062 B，比原1470432 B减少1280370 B。该阶段46张相同冻结View的PBM逐字节一致；这是旧布局离线证据，见[mono验收记录](acceptance.md#mono-字库第-1-阶段验证2026-10-28)。当前多字号、特大字和原创素材的尺寸以`.build/generated/assets.json`及[UI验收](acceptance.md#ui-与-ux-重写验收)为准。

这些限额未包含进度/轮次、View/UI 的其他分配、分配器元数据及对齐、64KiB 主任务栈、其他任务与平台服务。导入期间调用方输入缓冲（最多 64KiB）、旧活动内容和新候选会同时存在；解析已前移字段长度、集合数量和科目余额校验，超限逐项停止，仍存在 serde scratch 和 Vec 扩容临时重叠。存档输入缓冲另计。当前已有指定候选的 C3 heap/连续块及主任务栈样本，完整峰值、碎片化、其他任务栈和无线/SD 预留尚未闭合。容量门禁不能替代真机预算，样本见[当前运行内存证据](platform.md#当前运行内存证据)。

运行时仅接受固件已烘焙字形白名单。24px霞鹜新晰黑包含全部示范及课程文案、递归扫描`native/src/`得到的全部Rust运行时文案、ASCII、拼音预组声调及组合符号；32px与48px覆盖同一全集。旧24px / 48px Noto Regular保留原度量、明确UI字符源和示范card.front覆盖，供导入宽度契约、旧View与刷机最终提示使用。176 / 112px特大字也使用霞鹜新晰黑，仅覆盖内置front，导入内容可退回48px，不强制扩展特大字表。构建扫描源记录在`.build/generated/ui-font-sources.json`。新增汉字可能需要重新构建字形档案，导入不会下载字体或执行JS；当前引擎不承诺完整Unicode组合整形，拼音优先使用预组声调。

## 双槽存档

平台启动顺序为 create → 验证并连接匹配的SD课程，或导入平台现存小卡组 → load 两个保存槽。存档包含每轮 5/10 张设置、各科轮换位置、当前轮次稳定 ID 列表、游标、模式、翻面状态、逐题结果和复习进度。

每条记录最大32768字节，保留24字节头。新导出为版本2：`BALA`、版本/保留 `[2,0,0,0]`、LE u64 generation、LE u32 payload长度、LE u32 CRC32；payload包含轮次/设置JSON和按稳定32位键保存的稀疏课程进度。版本1的JSON payload仍可读取，旧“认识”只迁移为一次正确；详见[双槽迁移](curriculum.md#双槽迁移)。CRC 覆盖头部前 20 字节及 payload。加载先选择版本、长度、CRC 和数据语义都有效的最高 generation。只有对应科目已完整验证并成功导入卡组时，缺失 ID 才能作为合法删除迁移；内置回退卡组无法解释最高有效档中的轮次或进度 ID 时，保持当前状态并保护原档，不借更旧槽掩盖该问题。

真实入口在启动SD未挂载时跳过恢复，同时锁定模型存档导出并由平台阻断全部保存；执行恢复后，根目录不可用、任一槽 IO/内存不足、没有有效存档或上述 ID 无法解释时，模型在本次会话锁住全部存档导出。仅启动时两个槽都明确不存在可作为首次使用；C 存储重新初始化、回桌面、后续学习和重置不能解除已有保护。保护会清除待确认事务，迟到 ack 无效；只有成功 load 有效且可解释的存档才解锁。修复 SD/卡组后重新启动或完整复读有效档可恢复，临时学习不会覆盖原文件。保护标记与按科导入记录只在内存中；最高有效档中的未知课程身份或未知稳定键同样阻止导出。

平台调用 save_export 得到应覆盖的非活动槽、generation 和完整记录，只写该槽。写入后应落盘、读回核验再 save_ack(success=1)，失败须 ack(0)，保留另一个有效槽。一次仅允许一笔待确认事务；期间模型有新变化时不能覆盖原待写记录，必须先结束上笔。失败不清 dirty，成功也只清除导出之后没有新变化的 dirty。

宿主测试逐一模拟新记录所有截断点、损坏 CRC、单槽有效、两槽均坏、确认失败及确认期间继续作答。新增存储保护回归覆盖未读槽阻止导出、最高有效未知 ID 不回退旧槽、合法删除、跨重置保护与迟到 ack；实际 storage + Rust ABI + runtime 测试在唯一槽 IO 及自定义卡组缺失/损坏/IO 四种故障下，核验自动、显式和关机保存均不改原文件，修复后新启动逐字节恢复完整 Snapshot。真实 C ABI 回归覆盖空槽/双坏槽 load → 错误页 render 成功 → display_complete → 正面确认回桌面；完成显示前按正面键仍受门禁约束，错误不会困住退出操作。该方案不替代真实 SD 的原子性、文件系统落盘和掉电实验；CRC 用于意外损坏检测，不提供认证。

## 配网平台边界

家长设置的蓝牙配网页产生 NETWORK_START 请求，进入独占固定面板。状态为1等待手机、2连接网络、3成功、4失败、5取消、6超时、7准备、8关闭中、9清理失败。`network_info` 只接收本代11字节设备名与6字节ASCII数字PoP（允许前导0）；`network_phase` 同步 generation、准备阶段和明确资源释放标志；`network_ready` 校验精确 revision、同代同阶段和真实 display_complete，供平台提交下一阶段。布局单一来源、ABI门禁和状态表见[分阶段配网](staged-provisioning.md)。

平台已接入固定乐鑫 manager、NimBLE 和官方 Security 1。RECV/SUCCESS/FAIL/END 使用同步有界状态通道；等待手机来自 transport 实际广告启动成功。模型不接触 Wi-Fi 密码。两次准备帧释放 View/UI 后，活跃状态只修改原 framebuffer 中的标记/身份矩形并沿用 begin_render/display_complete；不再次构造 View、加载字体或执行完整 AOT。返回/Home/关机不受 ready 门禁，但只记录有界退出意图，资源安全释放前保留面板。清理故障撤销旧关机、停止自动保存和完整渲染；资源释放确认后才允许恢复，不能用 !active 推定安全。
