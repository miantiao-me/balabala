# 分阶段配网固定面板契约

逻辑尺寸为 480×800；正文 24px、设备名称及标题 48px Bold、黑白全屏刷新。唯一几何源是 [provisioning-layout.json](../native/provisioning-layout.json)，构建器据此校验 App.vue 固定分支并生成 Rust 反白/擦除常量。首帧全部状态文字一次生成，后续 BLE 活跃期只在原 framebuffer 更新状态反白和敏感区域。

```text
(24,24)  蓝牙配网                    [存储提示]
(24,106) 设备名称
(24,142) PROV_XXXXXX                 [身份擦除区 432×70]
(24,226) 配对密码
(24,276) [0] [1] [2] [3] [4] [5]    [身份擦除区 432×88]

(24,372) 配网进度
[准备] [连手机] [连网络] [已连接]     y412，102×56
[关闭中] [配网失败] [已取消]           y492，132×48
[已超时] [清理失败]                   y556，132×48

反白表示当前状态                     y628
手机打开乐鑫配网客户端               y666

```

第一行状态 x=24 / 134 / 244 / 354，后两行 x=24 / 174 / 324；完整状态矩形内部反白，任意状态仅一项反白。六个数字格的起点 x24、间距72、格宽64、高88。敏感区域采用半开边界 `[24,142,456,212)` 和 `[24,276,456,364)`；逻辑清除时整个区域置白，保留区域外的标签、状态和边框。

| 状态值 | 标记 | 进入条件 |
|---|---|---|
| 7 | 准备 | 空身份首帧，或RF熵生成本代身份后 |
| 1 | 连手机 | 本代 transport 实际广告启动成功 |
| 2 | 连网络 | 本代同步 RECV |
| 3 | 已连接 | 本代 SUCCESS，保留官方查询窗口 |
| 8 | 关闭中 | 已发取消/停止，等待完整清理 |
| 4 | 配网失败 | 失败且安全释放 |
| 5 | 已取消 | 取消且安全释放 |
| 6 | 已超时 | 原300秒截止且安全释放 |
| 9 | 清理失败 | 资源仍驻留或释放无法确认 |

状态7首帧身份为空、第二帧显示真实值；状态1/2保留身份，其余状态清空身份。

启动先保存 dirty，失败保留学习状态/dirty并进入可退出错误页；clean 不强制写SD。计时从本次准备开始，共300秒，包含两个显示门禁。先生成空身份准备面板，释放UI/View并等待真实ack；再采输入、校验generation/revision/阶段/请求/取消关机/截止后，执行 prepare→backup→esp_wifi_start→identity。此时 manager 尚未创建。再生成含真实11字节设备名和6字节ASCII数字PoP（允许前导0）的准备面板，释放UI/View并通过同样的精确ack门禁后，仅一次manager_init/start。首帧ack不能用于第二帧。

多出的空身份首帧使早期prepare/identity失败且release失败也有可信面板基底。只有上述两个准备帧允许完整AOT。raster在mount成功后才开始，失败mount不改原帧；完整生成后只更新合法基底。清理失败不能再次mount/View/font/draw或保存；固定面板继续接收去重的取消/Home/关机意图，撤销旧关机并锁止重开，无自动retry。

返回/Home/关机必须等资源释放确认后才能离开固定面板、完整AOT或保存。逻辑擦除先于显示；只有真实display_complete才代表对应帧完成。显示失败保留实际pending revision和有界重试，不声称物理屏已擦除。资源释放但原配置restore失败可进入完整错误页，仍锁止重开。

验收需要全部9状态PBM、空/真实身份和擦除矩形、边界外字节不变、反白状态切换可逆、两个门禁与各自取消/过期revision/generation/显示重试、早期每阶段故障加release失败、活跃期零AOT/零保存、恢复学习不重复评分。新页面布局及最新离线结果见[UI 重写验收](acceptance.md#ui-与-ux-重写验收)。以下为旧布局历史证据：拒绝START的P1修复及固定面板节点精简已通过宿主回归；同口径render峰49877 B，81张真实ABI最终帧一致，活跃overlay更新零分配。方向修正版phase2 z已完成指定设备的预热＋3轮自动生命周期，用户已确认屏幕方向正确。上述峰值与81帧比较属于原16位PoP阶段。旧16位普通 z 候选已独立Review并app-only部署校验，用户随后确认官方iPhone配网成功；本次6位PoP已审核并完成app-only部署、独立Flash校验和启动观察，尚未验证其手机交互或其他失败/退出/超时场景。宿主峰/drop、真机阶段采样与完整预算分别解释，全部动态heap或任务栈仍未闭合。当前证据及历史阶段的区分见[验收文档](acceptance.md#当前分阶段配网验证)；手机手动验收应使用关闭autotest且经过审核部署的普通候选，见[官方iOS步骤](ble-provisioning.md#官方-ios-操作路径)。
